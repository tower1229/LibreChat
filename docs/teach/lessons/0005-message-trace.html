一条消息的端到端 Trace

Mission：从点击发送到 MongoDB 落库

← Lesson 0004 · 速查表

本课只学一件事

把前四课拼起来：用户点发送后，代码如何穿过前端、HTTP、后端、LLM，再流式回到 UI 并写入数据库？

样本路径：Agents 端点（LibreChat 默认聊天模式）。Assistants 仍走旧的单连接 SSE，本课末尾对比即可。

总览：两阶段可恢复流

现代 Agents 聊天不是「一个 POST 一直挂着收流」，而是先启动任务，再订阅 SSE — 这样刷新页面、断网重连都能恢复。

前端 用户点发送 → ask() 构建 TSubmission，乐观更新 UI → Recoil submission 触发 useResumableSSE HTTP ① POST /api/agents/chat/agents ← { streamId, conversationId, status: "started" } HTTP ② GET /api/agents/chat/stream/:streamId (SSE) ← event: message data: { type, text, index } …逐字 ← event: message data: { final: true, … } …结束 后端 GenerationJobManager 在后台跑 client.sendMessage() → emitChunk → SSE 订阅者 → saveMessage() → MongoDB → final event

关键设计：streamId === conversationId（新会话时后端生成 UUID）。来源：api/server/controllers/agents/request.js

顺序：先 saveMessage，再 emit final event（避免客户端 refetch 时 DB 还没写完）

SSE 事件长什么样

useResumableSSE / useEventHandlers 按 JSON 字段分支处理（同一 message 事件名下）：

data 特征含义UI 效果
{ created: true, message }用户消息已在服务端创建同步真实 messageId
{ type, text, index }内容块增量流式打字、工具调用展示
{ event: 'title', title }新会话标题侧边栏标题更新
{ final: true, ... }生成结束停止按钮消失、可发下一条

Wire 格式：Server-Sent Events — event: + data: 行，双换行分隔。

动手：DevTools 里跟一条真实请求

本地跑起前后端，打开聊天页，发一条短消息，在 Network 面板：

  1. 找到 POST …/api/agents/chat/agents — Response 应是 JSON，含 streamId
  2. 找到 GET …/api/agents/chat/stream/<uuid> — Type 为 eventsource，EventStream 标签页看逐条 message 事件
  3. 生成结束后，刷新页面 — 消息仍在（已 saveMessage 进 MongoDB）
# 终端 A npm run backend:dev # 终端 B npm run frontend:dev # 浏览器 http://localhost:3090

后端日志可搜：[ResumableAgentController]、[AgentStream]

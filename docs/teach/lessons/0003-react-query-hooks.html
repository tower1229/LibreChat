React Query Hook 层

Mission：把 data-service 接到 React 组件

← Lesson 0002 · 速查表

本课只学一件事

第二课你 trace 到了 dataService.getStartupConfig()。本课回答：组件怎么订阅这份数据？缓存怎么管？

答案在 client/src/data-provider/ — LibreChat 前端的 React Query 适配层。

两层 data-provider，别混淆

包路径职责
共享契约 packages/data-provider types、endpoints、data-service、QueryKeys — 前后端共用
前端适配 client/src/data-provider useQuery / useMutation hooks，接组件

你在别的项目里可能把这两层合成一个 @org/api-client 包；LibreChat 刻意拆开，让后端也能 import 同一套 types 和 endpoints。

目录结构（按功能分文件夹）

client/src/data-provider/ ├── index.ts ← 统一 export，组件 import 自 ~/data-provider ├── queries.ts ← 通用 query hooks（会话、助手等） ├── mutations.ts ← 通用 mutation hooks ├── Endpoints/ │ ├── index.ts │ └── queries.ts ← useGetStartupConfig 在这里 ├── Auth/ ← 登录相关 hooks ├── Messages/ ├── Files/ └── ...

二开加新 API 时：先在 packages/data-provider 加三件套，再在对应功能文件夹加 queries.ts 或 mutations.ts，最后从 index.ts export。

样本：useGetStartupConfig 解剖

打开 client/src/data-provider/Endpoints/queries.ts：

export const startupConfigKey = (isAuthenticated, context?) => [QueryKeys.startupConfig, isAuthenticated, context ?? 'default'] as const; export const useGetStartupConfig = (config?, options?) => { const queriesEnabled = useRecoilValue(store.queriesEnabled); const user = useRecoilValue(store.user); return useQuery( startupConfigKey(!!user, options?.context), // ① 缓存键 () => dataService.getStartupConfig({ ... }), // ② 取数函数 { staleTime: Infinity, // ③ 启动配置几乎不变 refetchOnWindowFocus: false, ...config, enabled: (config?.enabled ?? true) && queriesEnabled, // ④ 门控 }, ); };

四个要点：

①
QueryKey 来自 packages/data-provider/src/keys.ts 的 QueryKeys 枚举。LibreChat 把 key 定义在共享包里，方便 mutation 后 invalidateQueries 时前后一致。
②
queryFn 只调 dataService.xxx()，不直接写 axios。Hook 层不管 URL 和类型，只管缓存策略。
③
staleTime / refetch 选项 按数据特性配置。启动配置用 Infinity；余额类数据会 refetchOnWindowFocus: true（见 Misc/queries.ts）。
④
enabled 门控：queriesEnabled（Recoil 全局开关）+ 可选的 config.enabled。未登录时不乱发需要鉴权的请求。

为什么 startupConfigKey 要带 isAuthenticated？

登录页和聊天页调同一个 /api/config，但响应字段不同（未登录走 buildPreLoginPayload）。

若缓存键相同，登录后可能读到登录前的「瘦」配置。
startupConfigKey(!!user, context) 把「是否已登录」编进 key，两份缓存互不污染。

同类模式：Share 页传 { context: 'share' }，key 第三段变成 'share'。

组件里怎么用

打开 client/src/components/Nav/SettingsTabs/About/About.tsx：

import { useGetStartupConfig } from '~/data-provider'; import type { TStartupConfig } from 'librechat-data-provider'; function About() { const { data: startupConfig } = useGetStartupConfig(); const buildInfo = startupConfig?.buildInfo; // ... }

组件只 import hook 和类型，不碰 data-service 或 endpoints。类型从 librechat-data-provider 包 import（即 packages/data-provider 编译产物）。

Query vs Mutation（先建立直觉）

Query（读）Mutation（写）
HookuseQueryuseMutation
典型文件*/queries.ts*/mutations.ts
KeyQueryKeysMutationKeys（仅标识，非缓存主键）
成功后自动更新缓存常 invalidateQueries 或 setQueryData
样本useGetStartupConfiguseUpdateConversationMutation

本课聚焦 Query；Mutation 的 invalidation 模式在后续「端到端小功能」课里练。

完整链路（复习 + 延伸）

About.tsx useGetStartupConfig() ← client/src/data-provider (本课) ↓ dataService.getStartupConfig() ← packages/data-provider (上节课) ↓ endpoints.config() → request.get() → /api/config → config.js

动手：在 IDE 找 3 个用法

  1. 全局搜索 useGetStartupConfig，挑一个组件看 data 怎么消费
  2. 打开 client/src/data-provider/index.ts，确认 Endpoints 被 re-export
  3. （可选）在 useChatFunctions.ts 搜 queryClient.getQueryData — 非 hook 场景下命令式读缓存

二开加新「读」API 的标准顺序

1. packages/data-provider — types + endpoints + data-service + QueryKeys（上节课）
2. client/src/data-provider/[Feature]/queries.ts — 写 useGetXxx
3. client/src/data-provider/[Feature]/index.ts + 根 index.ts — export
4. 组件里 const { data, isLoading, error } = useGetXxx()

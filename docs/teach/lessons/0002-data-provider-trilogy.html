data-provider 三件套

Mission：能 trace 一条 API 从 UI 到后端

本课只学一件事

掌握 LibreChat 的前后端契约层：packages/data-provider 里三个协作文件如何拼成一条可追踪的 API 调用。

用真实样本 getStartupConfig（应用启动配置，登录页和聊天页都会用）贯穿全课。

三件套分工

层文件一句话
① 路径api-endpoints.ts这个 API 的 URL 是什么
② 类型config.ts / types/请求和响应长什么样
③ 调用data-service.ts前端怎么发这个请求

类比：你们团队里的 @org/api-types + OpenAPI 生成的 client，但三件套拆得更细、且前后端共用。

样本代码（真实仓库）

① endpoints — 拼出 GET /api/config

// packages/data-provider/src/api-endpoints.ts export const config = (context?: StartupConfigContext) => `${BASE_URL}/api/config${buildQuery({ context })}`;

② types — 响应形状

// packages/data-provider/src/config.ts export type TStartupConfig = { appTitle: string; emailLoginEnabled: boolean; interface?: TInterfaceConfig; // ... 更多字段 };

③ data-service — 把 ① 和 ② 连起来

// packages/data-provider/src/data-service.ts export const getStartupConfig = (options?) => request.get(endpoints.config(options?.context)); // 返回类型：Promise<TStartupConfig & ...>

底层 transport — request.ts 用 axios，自动带 JWT cookie/header（你暂时只需知道「鉴权在这里统一处理」）。

端到端 Trace（5 站）

在 IDE 里按顺序打开（或 DevTools Network 过滤 config）：

1
React Query Hook
client/src/data-provider/Endpoints/queries.ts
useGetStartupConfig → 调用 dataService.getStartupConfig
2
data-service
packages/data-provider/src/data-service.ts → getStartupConfig
3
endpoint
packages/data-provider/src/api-endpoints.ts → config()
4
Express 挂载
api/server/index.js → app.use('/api/config', ..., routes.config)
5
Handler
api/server/routes/config.js → router.get('/') 组装 TStartupConfig 并 res.send(payload)
useGetStartupConfig() ↓ getStartupConfig() ← data-service ↓ endpoints.config() ← api-endpoints → GET /api/config ↓ request.get() ← axios ↓ routes/config.js ← 后端 handler ↓ JSON（应对齐 TStartupConfig）

动手：在浏览器验证

  1. 确保 npm run backend:dev 在跑
  2. 打开 http://localhost:3080/api/config（或登录后 DevTools → Network）
  3. 找到响应 JSON，对照 TStartupConfig 里的字段（如 appTitle、emailLoginEnabled）

未登录时 handler 走 buildPreLoginPayload() 分支——响应字段更少，这是刻意的安全设计。

来源：api/server/routes/config.js 注释说明匿名可读的字段范围。

二开时改 API 的标准顺序

新增或修改 REST API 时，按这个顺序动刀：

1. types/ 或相关类型文件 — 定义响应/请求形状
2. api-endpoints.ts — 加 URL 函数
3. data-service.ts — 加 getXxx / postXxx
4. keys.ts — 若前端用 React Query，加 QueryKey
5. 后端 route + packages/api 业务逻辑
6. npm run build:data-provider — 改 types 后必须 rebuild

✓ 检查理解

1. 你要新增 GET /api/widgets，第一步应该改哪个文件？

2. getStartupConfig 最终请求的 HTTP 路径是？

3. 修改 TStartupConfig 类型后，必须执行？

4. 动手题：按 trace 顺序，data-service.ts 的下一站文件是？（填文件名，不含路径）

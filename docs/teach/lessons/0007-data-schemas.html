本课只学一件事

Lesson 0006 你在 route 里调了 getBanner，但 DB 逻辑在 packages/data-schemas。本课回答：这个包怎么组织？新集合怎么加？和 data-provider 的 types 什么关系？

两个 types，别混

包例子用途
packages/data-providerTBanner、zod schemaHTTP 契约 — 前后端、API 响应
packages/data-schemasIBanner、Mongoose SchemaMongoDB 文档 — 持久化、查询

字段大多对齐，但职责不同：API 类型可 omit 内部字段；DB 类型可有 tenantId、索引、Meili 标记等。

目录三层：schema → model → methods

packages/data-schemas/src/ schema/banner.ts ← 字段定义、enum、timestamps models/banner.ts ← createBannerModel + applyTenantIsolation methods/banner.ts ← createBannerMethods → getBanner() ↓ 启动时注入 api/db/index.js createModels(mongoose) 注册所有 Model api/models/index.js createMethods(mongoose) 导出 getBanner, saveMessage, … ↑ legacy route: require('~/models')

样本 ① Banner（简单读）

Schema — 集合形状 + 索引 hint：

// schema/banner.ts bannerId, message, displayFrom, displayTo, type, isPublic, persistable tenantId: { type: String, index: true } { timestamps: true } → createdAt / updatedAt

Model — 注册到 Mongoose + 租户插件：

// models/banner.ts applyTenantIsolation(bannerSchema); return mongoose.models.Banner || mongoose.model('Banner', bannerSchema);

Methods — 工厂函数，返回可调用方法（你已在 IDE 里打开过）：

// methods/banner.ts export function createBannerMethods(mongoose) { async function getBanner(user?) { return Banner.findOne({ displayFrom: { $lte: now }, ... }).lean(); } return { getBanner }; }

createMethods 在 methods/index.ts 里 spread 合并所有 domain methods，所以 route 里直接 const { getBanner } = require('~/models')。

样本 ② Message（复杂写）

Lesson 0005 的 saveMessage 是 Tier 2 方法 — 带业务规则：

  • 校验 userId、conversationId UUID
  • 临时会话 retention（isTemporary + interfaceConfig）
  • upsert / 更新 content parts
  • MeiliSearch 同步（经 model plugin）

文件：methods/message.ts + schema/message.ts（meiliIndex: true 字段标记）

规律：简单 findOne 放 methods 即可；跨 collection、权限、缓存、事务 → methods 可注入 deps（见 createMethods(mongoose, { getCache, matchModelName, ... })）。

租户隔离 tenantIsolation

多租户部署时，带 tenantId 的 schema 在 model 层调用 applyTenantIsolation。插件会：

  • 在 find / update / aggregate 上自动注入当前 tenantId（来自请求上下文）
  • 阻止跨租户修改 tenantId
  • TENANT_ISOLATION_STRICT=true 时，无 tenant 上下文的查询会失败

来源：models/plugins/tenantIsolation.ts · config/tenantContext.ts（getTenantId、runAsSystem）

系统级任务（seed、migration）用 runAsSystem() 绕过租户 scope。

启动顺序（为什么 createModels 必须先跑）

connectDb() createModels(mongoose) ← api/db/index.js，Message/Conversation 等 Model 注册 indexSync() ← MeiliSearch 同步，依赖已注册的 Model createMethods(mongoose) ← api/models/index.js，业务方法就绪

注释写在 api/db/index.js：若 Model 未注册，Meili 同步会静默失败。

加新集合：5 步

步文件
1schema/foo.ts — Mongoose Schema
2types/foo.ts — IFoo 接口
3models/foo.ts + 加入 models/index.ts 的 createModels
4methods/foo.ts + 加入 methods/index.ts 的 createMethods
5route 使用 require('~/models').getFoo；API 契约仍走 data-provider

需 compound index / 迁移时，看 migrations/tenantIndexes.ts 模式 — 幂等 drop 旧索引。

测试怎么写

项目测试哲学：用 mongodb-memory-server 跑真实 Mongoose 查询，而不是 mock DB。

cd packages/data-schemas && npx jest message.spec

参考：methods/message.spec.ts、methods/banner 同级 *.spec.ts

动手：MongoDB 里看 Banner 集合

若本地 Mongo 在跑（backend:dev 已 connectDb）：

mongosh LibreChat --eval 'db.banners.find().pretty()' # 集合名通常是 schema model 名小写复数：Banner → banners

对照 getBanner 的 query 条件：displayFrom / displayTo / type / isPublic。
